What the branch actually contains

Grounding Context

Codebase context

Six tabs now expose provider attempts, sessions, models/connections, tools, subagents, and context snapshots through seven IPC queries. The diff includes roughly 7.5k added lines and a focused test suite that passes.

Current information shape

Overview alone has eight stat cards and seven charts. Specialist tabs repeat total spend, tokens, calls, and outcome distributions while presenting wide tables of raw counters.

Trust gaps

Some paths combine currencies, silently aggregate only 1,000 rows, lose the model dimension in a model trend, ignore the chosen date range in session detail, or stack token subcategories as if they were additive.

External pattern

Current LLM observability dashboards converge on trace-level cost, latency percentiles, errors, tools, quality scores, explicit filters, and drill-down from a spike to its contributing events.

Point of view: this is already enough telemetry for a useful v1. Correct the semantic foundation, simplify the landing page, and add turn-level latency/outcome before expanding the chart catalog.

1Trustworthy local ledger before more charts

Confidence 98%Complexity Medium

Make every cost and usage view explicit about currency, range, timezone, sampling, and category semantics. Add a small data-quality strip showing known-cost coverage, currencies represented, last event time, and whether the result is complete or top-N. Separate currency series rather than summing them, push aggregates into SQL, apply the global date filter to drill-down, and render token categories as mutually exclusive segments.

Axis
Financial truth and efficiency
Basis
direct: analytics-queries.ts:153-183 drops currency from the spend time series; analytics-queries.ts:539-554 aggregates model/connection cost without currency; Tools/Subagents/Context call listAll(DEFAULT_LIMIT) with DEFAULT_LIMIT = 1000; SessionsTab.tsx:73-75 loads lifetime session detail without the selected range. The Overview stack adds full output and reasoning even though cost.ts:144-149 recognizes reasoning may be a subset of output.
Rationale
A precise-looking wrong graph is worse than no graph. These fixes also create a reliable base for every later recommendation.
Downsides
Requires analytics result-shape changes, new SQL paths, and careful provider-specific token semantics. Currency conversion should remain out of scope unless a dated exchange-rate source is added.

2A decision dashboard, not a telemetry gallery

Confidence 94%Complexity Medium

Reduce Overview to six decision-grade widgets: spend trend, cost per turn/session, p95 turn latency, failed/retry tax, context-risk rate, and top expensive outliers. Each KPI should show change versus the preceding equal-length period and link to the filtered rows behind it. Move cost-source coverage to the trust strip; move tier/provider detail to specialist tabs; remove the two overview pies and the agent-tier call-count chart.

Axis
Information hierarchy and drill-down
Basis
direct + external: OverviewTab.tsx:42-144 currently renders eight cards and seven charts, several duplicated in later tabs. Langfuse Pulse explicitly makes an outlier bucket navigable to its underlying events; LangSmith prebuilt dashboards prioritize trace, latency, error, cost/token, and tool sections.
Rationale
The dashboard earns its space only when it shortens the path from “something changed” to “this component caused it.”
Downsides
Previous-period comparison needs careful behavior for All/custom ranges and sparse data. Removing charts may feel like lost scope unless the specialist views remain discoverable.

3Turn performance and waste

Confidence 91%Complexity High

Add a time series for p50/p95 end-to-end turn latency and time to first token, split by model or connection. Pair it with failed/retry tax: time, attempts, and known spend consumed by retries, provider failures, tool errors, timeouts, and interruptions. Clicking a spike opens the affected turns and groups failure causes into actionable categories.

Axis
Speed and reliability
Basis
direct + external: provider and tool records already carry start/completion timestamps and outcomes, but the UI shows totals or averages rather than tail behavior. LangSmith exposes p50/p99 latency and first-token latency; both LangSmith and Langfuse make latency and error rate core dashboard measures.
Rationale
Users experience the tail, not the mean. “Waste” turns reliability into an economic decision: which failures are both frequent and expensive?
Downsides
True turn latency and TTFT need turn-level lifecycle timestamps and a first-token event. Error taxonomy must avoid leaking sensitive provider/tool messages.

4A causal turn waterfall

Confidence 88%Complexity High

Introduce a turn-level trace that nests provider attempts, tools, waits, and subagents. Render one APM-style waterfall in Session Detail with wall-time bars and cost labels, highlighting the operations responsible for most latency and spend. Keep raw attempt/tool tables behind the waterfall for exact inspection.

Axis
Agent/tool workflow diagnostics
Basis
direct + external: the branch already stores provider_attempt_id on tool/context records, chain/turn IDs, parent chain IDs, and lifecycle timestamps. Langfuse describes nested trace observations as the primary debugging primitive and highlights each span's share of aggregate cost and latency.
Rationale
Separate tabs cannot explain causality or concurrency. A single trace answers whether the model, a tool, a retry, or delegation dominated the turn.
Downsides
Requires a stable trace/span model and overlap-aware wall-time math. It should start in Session Detail rather than expand the Overview scope.

5Context-risk explorer

Confidence 90%Complexity Medium–High

Replace the cross-session raw-token spaghetti chart with context fill percentage for a selected session or top-risk turns. Add the model limit, peak/median fill, composition, and markers for compaction, truncation, output offload, or unusually large tool results. A jump opens the exact turn and contributing tool result.

Axis
Context lifecycle
Basis
direct: ContextTab.tsx:42-59 overlays up to five sessions by timestamp and raw usedTokens; ContextTab.tsx:83-128 reports snapshot counts/averages without model limits or lifecycle events. The confirmed requirements originally named fill percentage, but the result type does not contain maxContext.
Rationale
Raw token counts are not comparable across models. Pressure plus lifecycle markers tells the user when context became risky and what caused the jump.
Downsides
Needs the frozen model context limit and new compaction/truncation events. Composition fields are estimates and should be labeled as such.

6Delegation efficiency, not subagent volume

Confidence 82%Complexity Medium–High

Reframe the Subagents tab around contribution: main-versus-subagent cost share, completion/failure rate, median duration, and estimated wall time saved by overlap. Compare agent name/tier only after normalizing per invocation or completed parent turn. Keep raw invocation and token totals as drill-down.

Axis
Agent/tool workflow diagnostics
Basis
direct: subagent attribution already records parent chain, status, timestamps, model, connection, agent name, and tier, while the UI currently leads with invocation count and total input/output. The causal timestamps can establish overlap even before a quality score exists.
Rationale
“We used Crown agents 37 times” is trivia. “Reviewers consumed 22% of cost and removed 31% of wall time with a 96% completion rate” informs tier and delegation choices.
Downsides
Parallel-time-saved is an estimate and needs a transparent formula. Completion is not the same as usefulness, so this becomes much stronger after Idea 7.

7Outcome-adjusted economics

Confidence 76%Complexity High

Add a lightweight task outcome attached to a turn or session: explicit thumbs up/down, accepted result, stopped/corrected/retried, or a small post-task rating. Then chart cost per successful turn and success rate by model, tier, workspace, and delegation mode. Technical success remains a reliability signal; user outcome becomes the value signal.

Axis
Financial truth and efficiency
Basis
external + reasoned: Langfuse treats user feedback, programmatic checks, and evaluation scores as the path from observing what an LLM does to measuring how well it does it. The branch currently records transport/tool/subagent outcomes only; a technically succeeded call can still produce unusable work.
Rationale
Without outcome, “cheapest model” and “best agent tier” are incomplete questions. This metric makes every cost comparison materially more useful.
Downsides
Feedback is sparse and selection-biased; inferred correction signals can be noisy. Start with explicit, optional feedback and report sample size rather than pretending to have objective quality.
